# RWords (сайт): перелік функціоналу

Файл ведемо як джерело для хелпів. Після кожної зробленої функції дописуємо сюди запис.

**Позначки статусу:** ✅ працює · ⏳ відкладено · 🔍 потребує перевірки (код не переглядався) · ⚠️ відомий нюанс

**Стек:** Next.js 16 (server actions), Postgres (`sql```), next-auth, bcrypt. Деплой: GitHub → Vercel (автодеплой).

## 1. Автентифікація та доступ

- ✅ Вхід через next-auth (`app/api/auth/[...nextauth]/route.js`, `authOptions`).
- ✅ `signIn` шукає користувача за email. Email адміна не використовувати як логін через OAuth.
- ✅ Адмін: користувач з `id = 1`, пароль у БД зберігається як хеш bcrypt. Сид адміна з коду видалено.
- ✅ `lib/requireAdmin.js`:
  - `requireAdmin()`: суворо, лише адмін.
  - `requireAdminOrBootstrap()`: для `initTables`; дозволено, якщо адміна ще немає.
- ⚠️ Помилки входу «No user» і «Invalid password» розрізняються (витік інформації про наявність акаунта). Заплановано одне загальне повідомлення.
- ⚠️ RLS-політики (`createRLSPolicies`) використовують `auth.uid()` (є лише в Supabase), ймовірно не працюють у поточній Postgres.

## 4. Плеєр слів

Файли: `app/hooks/useWordPlayer.js`, `app/components/study/StudyPlayer.js`. Повноекранна накладка, на `speechSynthesis`. Широкий екран: дві колонки (оригінал | переклад), вузький: один над одним. Кожен блок прокручується окремо, шрифт залежить від довжини тексту.

**Цикл слова:** оригінал → озвучка → пауза → переклад → озвучка → пауза → повтор перекладу → пауза → наступне слово. Паузи рахуються від справжнього кінця мовлення (`onend`).

**Налаштування за замовчуванням** (`DEFAULT_PLAYER_SETTINGS`):

| Параметр | Значення | Опис |
|---|---|---|
| `fromLang` | `uk-UA` | мова оригіналу |
| `toLang` | `en-GB` | мова перекладу |
| `rate` | `0.9` | швидкість мовлення |
| `delayOriginal` | `2000` мс | пауза після оригіналу |
| `delayTranslation1` | `1000` мс | пауза після перекладу |
| `delayTranslation2` | `1000` мс | пауза після повтору перекладу |
| `repeatTranslation` | `true` | повторювати переклад |
| `reverseOrder` | `false` | `true`: спочатку переклад, потім оригінал |

**Підсвітка речення** ✅: якщо в тексті більше одного речення, те, що зараз звучить, виділяється бурштиновою плашкою (світла й темна теми). Довгий текст прокручується за плашкою. Для одного речення нічого не змінюється. Підсвітка діє лише під час озвучки, у паузах її немає. Розбиття на речення робить експортована `splitSentences` (спільна для озвучки й відображення); речення довші за 180 символів озвучуються частинами, але підсвічуються разом. Між реченнями можлива коротка пауза.

**Кнопка 🌐 «До перекладу»** ✅: обриває оригінал і паузу після нього, показує переклад і одразу озвучує його, далі цикл іде як завжди. Неактивна, коли переклад уже показано. На паузі запускає плеєр з перекладу поточного слова. Команда хука: `skipToSecond`.

**Керування внизу:** ⏮ попередня тема · ◀ назад · ⏸/▶ пауза/грати · 🌐 до перекладу · ▶ далі · ⏭ наступна тема · ↻ повторити слово · ✕ закрити.

**Гарячі клавіші** (ігноруються в полях вводу):

| Клавіша | Дія |
|---|---|
| Пробіл | пауза / грати |
| → / ← | наступне / попереднє слово |
| ↓ / ↑ | наступна / попередня тема |
| `R` (або `К`) | повторити слово |
| `T` (або `Е`) | до перекладу |
| `Esc` | зупинити й закрити |

**Команди хука:** `start`, `pause`, `resume`, `toggle`, `repeat`, `skipToSecond`, `next`, `back`, `nextTopic`, `prevTopic`, `stop`.

**Голоси та браузери:**
- Попередження про відсутній голос (`missingLangs`) коректне.
- Chrome на Windows не має українського голосу. RHVoice (SAPI 5) у Windows встановлюється, але Chrome його голоси не показує.
- ✅ **Edge** має онлайн-голоси Microsoft, українська озвучка там працює. Для себе: відкривати сайт в Edge. Edge на тому ж рушії Chromium, розширення з Chrome Web Store працюють.
- Англійська озвучка працює через `speechSynthesis` у Chrome.
- Якщо інші користувачі захочуть українську: встановити голос RHVoice (і перевірити в своєму браузері) або користуватись Edge.
- Є страховий таймер на випадок, якщо `onend` не прийшов (особливість Chrome).

## 5. Імпорт CSV (універсальний)

Файли: `lib/importParser.js` (парсер), `app/actions/words/wordActions.js` (`importCSV`, `importBatch`), `app/words/page.js` (`handleFileUpload`).

**Структура файлу:**

```
// коментар
**Назва секції;посилання-секції
*Назва теми;посилання-теми
#колонки;слів;цього;файлу
рядок;слова;...
```

- `//` коментар · `**` секція · `*` тема · `#` заголовок колонок (може стояти в будь-якому місці; діє на рядки після нього).
- **Заголовок** задає, які колонки є і в якому порядку. Назви (нечутливі до регістру): слово/word/оригінал, переклад/translation, група/group/group_key, тип/type, посилання/link/img/image/картинка. Невідомі колонки ігноруються. Обов'язкова хоча б «слово» або «переклад».
- **Без заголовка** колонки за старою схемою: `слово;група;тип;переклад;посилання`, у звичайному порядку, **без реверсу**. Щоб поміняти місцями оригінал і переклад, достатньо в заголовку поставити `переклад` першою колонкою.
- Розділювач (`;`, `,` або Tab) визначається за заголовком. Клітинки можна брати в лапки (`;` усередині не ламає рядок). Підтримується BOM з Excel.
- Автозаповнення: `group_key` = слово, якщо воно одне; `type` = `word` (одне слово), `sentence` (закінчується на `.`, `?`, `!`, `…`) або `phrase`.
- Посилання секції й теми записуються в `sections.link` і `topics.link`.
- **Дублікати:** слово пропускається, якщо в цій темі вже є рядок, що збігається за всіма заповненими полями (слово і/або переклад). Секції шукаються за назвою, теми за назвою в межах секції. Дублікати всередині самого файлу теж пропускаються.
- Файл розбивається на батчі по 50 слів; прогрес у повідомленні; підсумок «імпортовано / пропущено дублікатів».
- ⚠️ Не підтримуються клітинки з переносом рядка всередині лапок.
- ⚠️ Після деплою відкриту вкладку треба оновити (Ctrl+F5), інакше помилка «Server Action ... was not found».
- ⏳ Імпорт з Excel (`.xlsx`) і Google Sheets: заплановано (потрібен пакет SheetJS).
